# IPA Pocket 0.3.0 — инструкция на русском

IPA Pocket — собственный веб-сайт для анализа IPA и экспериментальной попытки переподписания под конкретный iPhone через Apple ID. ПК с Windows 7 32-bit используется только как браузер; SideSign и Node.js собираются/запускаются на облачном сервере.

## Что нового в 0.3.0

- Добавлена экспериментальная серверная интеграция с открытым CLI [SideSign](https://github.com/SideStore/SideSign).
- После анализа IPA можно указать Apple ID, пароль, UDID и ответить на запрос двухфакторного подтверждения в интерфейсе.
- Сервер пытается войти в Apple Developer, зарегистрировать UDID и Bundle ID, создать/получить сертификат и provisioning profile, а затем переподписать IPA.
- Пароль не записывается самим приложением в файл и не добавляется в журнал приложения; во время входа он передаётся аргументом краткоживущему процессу SideSign. Временные рабочие файлы удаляются по завершении задания. Сессионные данные SideSign и development `.p12` кэшируются в `DATA_DIR/signing-cache`, чтобы не запрашивать новый сертификат при каждом действии; пароль кешированного `.p12` зашифрован ключом, производным от `ACCESS_KEY`.

## ВАЖНО — прочитай до Apple ID

1. Вход реализован через сторонний open-source CLI SideSign и протоколы Apple Developer, а не официальный OAuth/API авторизации. Apple может отказать во входе, потребовать 2FA или изменить серверный протокол.
2. Введённые Apple ID, пароль и ответы 2FA проходят через твой экземпляр IPA Pocket в Render. Render — облачный хостинг, поэтому это не то же самое, что вводить пароль непосредственно на apple.com. Для теста лучше отдельный Apple ID. Не вводи пароль, если не готов доверить обработку этому серверу.
3. Для бесплатной Personal Team нужен настоящий UDID iPhone: его надо зарегистрировать в аккаунте. UDID — 40 hex-символов, не IMEI и не серийный номер. На Windows его обычно можно увидеть в iTunes, нажав на поле Serial Number подключённого устройства.
4. Бесплатная подпись имеет ограничения, обычно требует повторной подписи примерно через 7 дней, ограничена числом активных приложений/идентификаторов, а приложения с push, App Groups, ключницами или особыми entitlements могут не работать после переподписания.
5. Текущий код — экспериментальная интеграция, не проверенная end-to-end на Apple ID реального пользователя. Первое развертывание должно быть проверено по Deploy Logs и через один тестовый IPA. Ошибки CLI будут показаны в журнале задания; не отправляй никому пароль или код.
6. OTA установка доступна только через публичный HTTPS URL и лишь после того, как IPA включает profile/signature clues. Это базовая проверка структуры, а не полноценная гарантия, что iOS примет подпись.

## Обновление существующего GitHub/Render проекта

Ты уже создал репозиторий `ipa-pocket` и Render Blueprint. Для обновления скачай `IPA-Pocket-0.3.0-AppleID.zip`, распакуй и замени файлы в корне существующего репозитория:

- `Dockerfile`
- `package.json`
- `render.yaml`
- `server.js`
- всю папку `public` (`index.html`, `style.css`, `app.js`)
- `README.md`

На GitHub нажми **Add file → Upload files**, загрузи файлы и подтверди **Commit changes**. Не удаляй и не меняй `ACCESS_KEY` в Render. После commit Render начнёт автоматически собирать новый образ. Сборка теперь значительно тяжелее, потому что Dockerfile собирает SideSign на Swift; если сборка завершится с ошибкой, открой Render → `ipa-pocket-ota` → Events/Deploys → View Logs и исправь ошибку прежде, чем использовать Apple ID.

Blueprint задаёт `DATA_DIR=/var/data`. В текущем бесплатном Render файловая система не постоянная: при перезапуске/повторном развёртывании может исчезнуть кеш SideSign и сертификат. Для сохранения сессии и сертификата на постоянной основе нужен persistent disk, если он доступен для выбранного тарифа. Не меняй `ACCESS_KEY` после того, как сертификат закеширован: пароль кеша зашифрован ключом, производным от этого значения.

## Первичный запуск

1. Дождись, пока Render показывает `Live` после успешной новой сборки. Убедись, что deployment, созданный после обновления, успешен.
2. Открой `https://ipa-pocket-ota.onrender.com`, введи прежний `ACCESS_KEY`.
3. Выбери IPA → **Извлечь данные и подготовить установку**.
4. На шаге **Подписать для моего iPhone** введи Apple ID, пароль, UDID и отметь предупреждение. Пароль очищается с формы сразу после отправки.
5. Если SideSign выводит запрос подтверждения, введите ответ/код в появившемся поле. Не отправляй коды в чат.
6. Если статус `completed`, скачай подписанный IPA либо попробуй **Установить на iPhone** в Safari. Если задача завершилась ошибкой, журнал покажет этап и последние строки ответа. Не отправляй сюда пароль или код 2FA; достаточно скриншота ошибки, где они не отображаются.

## Подпись и ограничения OTA

Веб-манифест `itms-services` сам по себе не подписывает приложения. iOS требует действительную подпись и provisioning profile, в котором зарегистрировано устройство. IPA Pocket не отключает защиту iOS и не обещает, что каждый произвольный IPA удастся переподписать.

## Проверки

```sh
npm run check
```

`GET /health` возвращает состояние веб-сервиса. Docker-образ собирает SideSign из его исходного репозитория и включает CLI `sidesign`.
