# IPA Pocket OTA 0.2.0 — инструкция на русском

**Главная функция:** принять твой `.ipa`, прочитать метаданные приложения и сформировать OTA-ссылку, которую можно открыть в Safari на iPhone.

## Честно о том, что делает эта версия

Эта версия **не подписывает IPA и не входит в Apple ID**. Она анализирует `Payload/*.app/Info.plist`, проверяет наличие характерных файлов профиля/подписи и размещает исходный IPA с временной ссылкой. Затем создаёт OTA manifest для протокола `itms-services`.

Это позволяет установить уже подходяще подписанный IPA через поддерживаемый iOS механизм. **Нельзя гарантировать установку любого файла:** IPA должен иметь подпись, которой доверяет iOS, подходящий provisioning profile и разрешение на установку на конкретное устройство. Наличие `embedded.mobileprovision` и `_CodeSignature/CodeResources` — только подсказка, не криптографическая проверка.

Нормальный OTA-механизм требует публичный HTTPS-сайт и доступный по HTTPS файл IPA. См. документацию Apple: https://support.apple.com/guide/deployment/deploying-proprietary-in-house-apps-depce7cefc4d/web

## Самый подходящий вариант для Windows 7 32-bit: разместить на Render

Старый ПК нужен только для браузера. Сам веб-сервис запустится в облаке.

1. Скачай и распакуй `IPA-Pocket-0.2.0-OTA.zip`.
2. Создай репозиторий на https://github.com/ . В репозиторий загрузи **содержимое** папки `ipa-pocket-ota` (в том числе папку `public`, `Dockerfile` и `render.yaml`). Не загружай `.env`, пароли, личные сертификаты или IPA.
3. Создай аккаунт на https://render.com/ . В панели Render выбери **New → Blueprint** и подключи свой GitHub-репозиторий.
4. Render прочитает `render.yaml` и попросит задать переменную `ACCESS_KEY`. Придумай уникальный длинный пароль (не меньше 20 символов), сохрани его у себя. Это ключ входа в IPA Pocket, **не пароль Apple ID**.
5. Запусти развертывание. Дождись статуса Live, затем открой домен вида `https://имя-сервиса.onrender.com`.
6. Введи свой `ACCESS_KEY`, загрузи IPA с iPhone или компьютера. Сервис покажет Bundle ID, название, версии, минимальную iOS и признаки профиля/подписи.
7. Нажми **«Установить на iPhone»** в Safari. Если IPA подходит устройству, iOS начнёт установку. Подтверди системные запросы и, если требуется для типа подписи, настрой доверие/режим разработчика.

Если GitHub/Render не предлагает Blueprint, создай в Render **New → Web Service**, подключи репозиторий и выбери Docker. Добавь переменную окружения `ACCESS_KEY` со своим длинным уникальным паролем. Остальные настройки берутся из `Dockerfile`.

## Использование

- Выбирай IPA с расширением `.ipa`.
- После анализа получаешь кнопку установки и прямую ссылку на исходный IPA.
- Ссылки имеют случайный секретный токен, доступны без входа только потому, что системному установщику iOS нельзя передать cookie веб-панели, и истекают через 2 часа по умолчанию.
- Если нажать «Скопировать ссылку установки» на ПК, можно передать её себе и открыть в Safari на iPhone. Проще всего — открыть сам сайт IPA Pocket в Safari, загрузить файл из «Файлов» и нажать установку прямо на телефоне.

## Установка локально (для более нового ПК/сервера)

Нужен Node.js 20.19+.

```sh
cp .env.example .env
```

Отредактируй `.env`, задай `ACCESS_KEY` (не менее 16 символов) и запусти:

```sh
npm install
npm start
```

Открой `http://localhost:3000`. **Это локальный режим только для анализа IPA:** ссылка установки не появится без публичного HTTPS. Нельзя использовать локальный `http://` URL для OTA-установки iPhone.

## Важные ограничения Render Free

- У бесплатного веб-сервиса временное хранилище. IPA и ссылки могут перестать работать после перезапуска или redeploy; загружай файл непосредственно перед установкой.
- Бесплатный сервис может «засыпать», а большие IPA могут упереться в лимиты загрузки/временного диска хостинга. Проект по умолчанию допускает файл до 2 GiB, но ограничения платформы могут быть ниже.
- Пока файл доступен, URL IPA может быть открыт без входа в панель. Секретный токен является ссылкой-доступом; не делись ею с другими. Файлы удаляются после истечения ссылки при очередной очистке.
- Не публикуй сайт без `ACCESS_KEY`, не добавляй пароль Apple ID/коды подтверждения в формы и не коммить IPA или сертификаты в GitHub.

## Что не реализовано

- Автоматическая Apple ID авторизация/двухфакторное подтверждение.
- Получение сертификатов и provisioning profiles из Apple Developer API.
- Переподписание IPA.
- Полная криптографическая проверка подписи и UDID-совместимости.
- Поддержка MarketplaceKit web distribution: она требует отдельного одобрения Apple и другого протокола.
